# Dr Vocal v2 (étapes 1 et 2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Faire de Dr Vocal une app de fond fiable (démarrage, icône, pause), corriger Spotify (titres, alias, répétition, aléatoire), régler Discord en local (volume par personne, mute, sourdine), puis ajouter un « cerveau » qui comprend les phrases libres en choisissant parmi les actions du catalogue.

**Architecture:** On garde le processus Python unique et le catalogue fermé. Un superviseur lancé par une tâche planifiée relance l'app si elle plante. Un état partagé (`ListenState`) relie l'icône, le micro et la boucle principale. Le catalogue devient une liste de fiches (`ActionSpec`), qui sert à la fois à valider toutes les intentions et à décrire les actions au modèle de langage. Celui-ci n'est appelé que si les règles échouent.

**Tech Stack:** Python 3.12+ (uv), sounddevice, openWakeWord, faster-whisper, piper-tts, spotipy, discord.py, claude-agent-sdk, pywebview, pystray + Pillow (nouveau), Ollama (essai local, hors dépendances Python), pytest.

**Spec:** `docs/superpowers/specs/2026-11-04-dr-vocal-v2-design.md`. Elle prolonge `docs/superpowers/specs/2026-11-02-dr-vocal-design.md`. Lire les deux.

## Global Constraints

- Windows 11, usage personnel, un seul utilisateur. Branche de travail : `feat/dr-vocal`.
- Seules les actions du catalogue sont exécutables. Un modèle de langage choisit une action du catalogue avec des arguments validés, ou ne fait rien. Il n'exécute jamais de code ni de commande système.
- Aucune action ne supprime de fichier, ni ne ferme le jeu ou Discord.
- L'audio ne quitte jamais le PC. Seuls le texte transcrit et les noms connus (projets, alias et bibliothèque Spotify, salons et membres Discord) partent, et seulement vers le moteur Claude, après un réveil, quand les règles n'ont rien compris.
- Aucune touche n'est simulée vers le jeu par défaut. Aucune fenêtre ni icône ne prend le focus.
- Pas de clé API Anthropic : `ANTHROPIC_API_KEY` et `ANTHROPIC_AUTH_TOKEN` restent retirées (`claude_session.scrub_environ`).
- Pas de voix par défaut. La voix ne sert qu'à relire un message Discord, aux questions de Claude, et à annoncer une action sensible choisie par le modèle.
- Une confirmation vocale ne s'accepte que par « oui docteur » (`claude_policy.parse_reply`).
- Secrets dans `secrets.toml`, jetons dans des fichiers cache à la racine, tous ignorés par git.
- Cibles inchangées : veille < 2 % du processeur total et < 300 Mo de RAM ; < 1 s de la fin de phrase à l'action pour une commande reconnue par les règles ; délai du cerveau ≤ 8 s.
- Style du dépôt : messages, journal et commentaires en français ; tests pytest avec réseau et matériel simulés ; fonctions pures pour tout ce qui se teste.
- Chaque tâche met à jour `README.md` et `config.example.toml` pour ce qu'elle ajoute.

## Review Focus

1. « mets en boucle » (répétition) contre « mets ma playlist en boucle » (alias de playlist) : la phrase qui contient « playlist » lance la playlist, la phrase courte règle la répétition (Task 6 et Task 7).
2. Le modèle renvoie une action valide avec un projet inventé ou des arguments en trop : `validate` rejette, son d'échec, aucune action (Task 11).
3. « Baisse Alex » quand Discord est fermé ou que l'utilisateur n'est dans aucun salon vocal : son d'échec, pas de plantage, le reste continue (Task 9).
4. Limite d'abonnement Claude atteinte, ou Claude Code déconnecté, pendant un appel du cerveau : `None` après le délai, son d'échec, les règles continuent de marcher (Task 12).
5. Écoute en pause pendant que Claude pose une question : rien n'est écouté, la demande reste en attente sur le deuxième écran (Task 4).
